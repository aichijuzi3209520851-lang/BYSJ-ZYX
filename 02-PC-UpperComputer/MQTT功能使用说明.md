# 智能温室上位机 - MQTT 功能使用说明

## 功能概述

智能温室上位机（WinForms，程序集 `智能温室.exe`）通过串口接收 STM32 下位机采集的环境数据，
解析后实时发布到本地或局域网内的 EMQX MQTT 服务器，供微信小程序等设备订阅，
同时订阅控制主题、将远程指令透传到串口，实现"手机 → MQTT → 串口 → 单片机"的远程控制链路。

## 系统链路

```
STM32下位机 ──串口(9600, 8N1)──▶ PC上位机(智能温室.exe) ──MQTT(TCP 1883)──▶ EMQX 服务器
                                      ▲                                        │
                                      └────── 订阅控制主题并转发串口 ◀── 微信小程序(WebSocket 8083) / MQTTX
```

## 默认配置（三端统一，请勿混用旧值）

| 配置项 | 值 | 说明 |
| --- | --- | --- |
| MQTT 服务器 IP | `192.168.36.221` | 上位机与小程序使用**同一台** EMQX 服务器 |
| 上位机连接端口 | `1883` | MQTT over TCP |
| 小程序连接端口 | `8083` | MQTT over WebSocket |
| 上位机发布主题 | `green/data` | 传感器 JSON 数据 |
| 上位机订阅主题 | `green/control` | 远程控制指令（原文转发串口） |
| 小程序订阅主题 | `green/data` | 与发布主题一致（小程序端默认留空，首次使用必须手动输入） |

> 注：上位机界面中主题为可编辑输入框，部署时只需保证 **发布主题 = 小程序订阅主题** 即可。

## 统一报警阈值（三端一致，固件为权威判定源）

| 指标 | 报警条件 | 固件动作 | 常量定义 |
| --- | --- | --- | --- |
| 温度 | > 26 °C | 黄灯 + 舵机开窗(180°) | `ALARM_TEMP_MAX` |
| 空气湿度 | > 85 %RH | 黄灯 + 舵机开窗(180°) | `ALARM_HUMI_MAX` |
| 土壤湿度 | > 40 %（过湿） | 蓝灯 | `ALARM_SOIL_MAX` |
| 空气质量 | 烟雾传感器判定 bad | 红灯 + 浓烟灯 + 电机全速排风 | — |
| 任一报警 | — | 蜂鸣器 + 上报 Warning | — |

上位机与小程序不再各自维护阈值，报警展示直接依据同一组数值与固件上报的 `Warning` 标志。

## 数据协议

### 串口数据帧（STM32 → 上位机，以 `\r\n` 结尾）

```
Temp:26C   Humi:60%RH   Soil:35%(raw=1200)  Light:72%  Servo:OFF Motor:OFF  Air:nice
```

- `Soil:` 为土壤湿度百分比（D2-5-2K 电容式，固件端已做反比映射）；`raw` 为 ADC 原始值，便于校准
- `Light:` 为光照强度百分比（光敏电阻 ADC1_IN9，仅采集展示，不参与报警联动）
- `Warning` 字样出现在行尾表示固件判定报警

### MQTT 发布 JSON（主题 `green/data`，QoS 1）

```json
{
    "timestamp": "2026-10-25 15:30:45.123",
    "temperature": 26,
    "humidity": 60,
    "soilMoisture": 35,
    "lightPercent": 72,
    "airQuality": "nice",
    "servoStatus": "OFF",
    "motorStatus": "OFF",
    "alarmType": "正常",
    "hasAlarm": false
}
```

- `soilMoisture`：土壤湿度百分比（v2.3 起由旧字段 `waterLevel` 更名，语义已从"水位"更正为"土壤湿度"）
- `lightPercent`：光照强度百分比（0–100，来自串口 `Light:` 字段；固件未提供光照阈值，故仅作展示字段）
- `hasAlarm`：按统一阈值计算的总报警标志，小程序据此显示报警横幅并震动提醒

### 远程控制指令（主题 `green/control` → 原文透传串口）

| 指令 | 作用 |
| --- | --- |
| `mode-0` / `mode-1` | 切换自动 / 手动模式 |
| `DUOJ-0` / `DUOJ-1` | 天窗舵机关(0°) / 开(180°)，仅手动模式生效 |
| `MOTOR-0` / `MOTOR-1` | 风扇电机停 / 全速，仅手动模式生效 |

USART1 与 USART3 使用同一套指令解析，行为完全一致。

## 使用方法

### 步骤 1: 启动 EMQX 服务器

推荐使用 MQTT-Project 工程中的"EMQX 一键启动器"（`MQTT.exe`）：
双击运行即自动定位 EMQX、后台启动、等待就绪并打开浏览器控制台；
命令行执行 `MQTT.exe stop` 可停止服务器。

也可以手动操作：

1. 进入 EMQX 目录：`cd emqx-5.0.26-windows-amd64\bin`
2. 启动：`.\emqx.cmd start`；停止：`.\emqx.cmd stop`
3. 验证：浏览器访问 `http://localhost:18083`，默认账号 `admin` / 密码 `public`

### 步骤 2: 配置上位机 MQTT 连接

1. 打开智能温室上位机
2. 在控制面板右侧 MQTT 区域填入服务器地址：`192.168.36.221:1883`
   （本地测试可用 `127.0.0.1:1883`）
3. 确认发布主题 `green/data`、订阅主题 `green/control`
4. 点击"连接 MQTT"，状态指示器变绿"已连接"即成功
5. 勾选"自动发布数据到 MQTT"后，每收到一帧串口数据即自动发布

### 步骤 3: 微信小程序端

1. 开发者工具导入 STM32-IoT-Greenhouse-we-chat-app 工程，勾选"不校验合法域名"
2. 进入"传感器"标签页 → 点击"配置"
3. 服务器地址填 `192.168.36.221`，端口 `8083`，订阅主题填 `green/data`（**必须手动输入**）
4. 点击"保存并连接"；连接成功后该配置自动存入历史，下次直接在历史记录中选用
5. 连接成功后即可看到五项环境数据（温度 / 空气湿度 / 土壤湿度 / 光照 / 空气质量）实时刷新；报警时页面出现红色横幅并伴随手机震动

### 步骤 4: 断开连接

- 上位机点击"断开 MQTT"；程序关闭时会自动断开
- 小程序点击"断开"；异常断开时小程序会以 2s/4s/8s 退避自动重连最多 3 次

## 常见问题

### Q1: 连接 MQTT 失败怎么办？
1. 访问 `http://localhost:18083` 确认 EMQX 已启动
2. 检查服务器地址、端口（上位机 1883 / 小程序 8083）、防火墙
3. 局域网访问需确认手机/开发板与服务器在同一网段

### Q2: 小程序订阅成功但收不到数据？
1. 确认上位机已连接 MQTT 且"自动发布"已勾选
2. 确认小程序订阅主题与上位机发布主题**完全一致**
3. 确认串口已连接且数据解析成功（日志出现"解析成功"）

### Q3: 土壤湿度一直显示 0？
v2.2 及更早版本按 `Water:XX%` 解析，而固件输出 `Soil:XX%(raw=XX)`，
v2.3 已同步修正；若仍为 0 请确认上位机为最新版本、固件串口输出含 `Soil:` 字段。

### Q4: 端口 18083 / 1883 / 8083 的区别？
- `1883`：MQTT over TCP，上位机连接使用
- `8083`：MQTT over WebSocket，微信小程序连接使用
- `18083`：EMQX Dashboard 网页管理端口，仅浏览器使用

## 技术说明

- **QoS**：发布 AtLeastOnce (QoS 1)；Retain 关闭；Clean Session 开启
- **客户端 ID**：`DHT11_Client_[GUID]`，每次连接唯一，避免冲突
- **小程序保活**：CONNECT keep-alive 60s，每 30s 发送 PINGREQ 心跳，异常断开指数退避重连
- **发布频率**：跟随串口数据帧（固件 1.5 秒/帧），无额外延迟

## 版本信息

- **程序名称**：智能温室大棚监控系统（上位机）
- **版本**：v2.4（稳定性修复版）
- **更新日期**：2026-10-25
- **v2.4 变更内容**（按代码审查结果修复，行为对用户可见的部分）：
  - 串口解析改为逐字段容错：`Temp:`/`Humi:` 缺失时不再整帧丢弃，土壤/光照/执行器/空气字段仍照常更新
  - 温度正则支持负号（`Temp:-5C` 可正确解析），并兼容 `Humi:` 单位大小写
  - 图标不再每帧 `Image.FromFile` 重新加载（改为缓存 + 统一释放），长期运行不再持续泄漏 GDI 句柄
  - 视频流 HttpClient 改为单例复用（原每帧新建，会耗尽套接字）
  - MQTT 消息处理器加挂载标记，断线重连后不再重复挂载导致同一条控制指令被执行多次
  - MQTT 重连、串口读线程、视频拉流线程均补 try/catch，异常不再导致整个进程崩溃
  - 日志框限制 6 万字符上限，长时间运行不再无限膨胀拖慢界面
  - 窗口关闭时统一释放串口、MQTT 客户端、HttpClient、图标缓存与定时器
- **v2.3 变更内容**：
  - 土壤湿度解析由 `Water:XX%` 同步为固件实际输出 `Soil:XX%`
  - MQTT 数据字段 `waterLevel` 更名为 `soilMoisture`
  - 报警阈值三端统一（温度>26 / 湿度>85 / 土壤>40 / 空气 bad）
  - 默认服务器 IP 与微信小程序同步为 `192.168.36.221`
  - 默认主题调整为 `green/data` / `green/control`
