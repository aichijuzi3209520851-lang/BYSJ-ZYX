# IotLinkLab 程序图标 · 设计说明

**产出**：`icon/app.ico`（7 档尺寸）、各档 `preview-*.png`、`compare-emqx.png`
**生成脚本**：`generate_icon.py`（正式）、`verify_icon.py`（验收自检）
**探索脚本**：`explore_*.py`（24 轮，过程图在 `_ref/`）

---

## 1. 为什么必须换

`05-Testing-Tool/WinFormsApp1/app.ico` 与 `03-EMQX-Server/app.ico` 原本是**字节完全相同**的同一个文件：

| 文件 | 字节 | sha256（前 16 位） |
|---|---|---|
| `03-EMQX-Server/app.ico`（保持不动） | 87883 | `c6367851930dc0b8` |
| `05-Testing-Tool/WinFormsApp1/app.ico`（旧值） | 87883 | `c6367851930dc0b8` |

两者都是单尺寸 256×256 ICO。结果 `IotLinkLab.exe` 和 EMQX 一键启动器 `MQTT.exe` 在资源管理器/任务栏里长得一模一样，无法区分。

本方案重新设计 `IotLinkLab` 的图标，EMQX 启动器图标**保持原样不动**。

## 2. 最终方案

**视觉母题：示波器/串口线上的一次信号跳变 —— 低电平 → 上升沿 → 高电平。**

一个正交折线，三笔：左低段、垂直上升沿、右高段。圆头圆角，无箭头、无文字。

### 为什么是「单边沿」而不是「脉冲波形」

这是 24 轮实测里最硬的一条结论：

- **对称双足波形**（低—高—低，左右两足等长）在 16px 几乎**必然**被读成 `Π` / 桌子 / 订书钉 / 订书机。v2、v3、v4 全部栽在这里，round20 的 A1–A5 又复现了一次。
- **单边信号沿**没有左右对称性，这个读法不成立。round21 的 E1/E2/E4 与 round23 的 H1–H7 在 16px 全部干净。

它同时是**专用语义**而非通用 UI 字形：
- 不同于 v1 的 ⇕ 双向箭头（那是「排序/交换」，任何 App 都能用）；
- 不同于 `>_` 终端提示符（通用开发者符号，round21 F 族，虽最锐利但与产品不特异）；
- 它表达的是这个程序真正在做的事：**MonitorTab 抓串口帧、画实时曲线、看信号跳变**。

### 为什么是「饱和底板」而不是浅色底板

用户在 `Theme.cs` 里明确要求「浅色科技感、禁全黑/大深色底」，所以我一度完全放弃深底（v2/v3 浅底波形）。但 `_ref/round23-realcontext.png` 的实拍对比推翻了这个做法：

> 淡雅底板 + 绿色线条在白底资源管理器里，视觉重量**远低于** EMQX 的青色色块。16px 下看起来像「空图标 / 坏图标」，不像产品图标。

Windows 程序图标需要**饱和底板撑起视觉重量**。v1 的真正错误是**那个通用双箭头字形**，不是饱和底板本身。这个区分很关键 —— 之前一直在改错变量。

## 4. 与 EMQX 图标为何不会混淆

见 `compare-emqx.png`（白 / `#F0F0F0` / `#202020` 三种背景，16→256px 全档并排）。

EMQX 图标：青色→蓝色**对角**渐变圆角块 + 白色弧形 WiFi 波纹 + 白色对角纸飞机。

| 维度 | EMQX 启动器 | IotLinkLab | 差异 |
|---|---|---|---|
| 色相 | 青 `#26D0CE` → 蓝 `#2A7FE0` | 绿 `#1B8F46` → 深绿 `#0C5228` | 青蓝 vs 纯绿，色相完全不同 |
| 明度 | 高亮、发光感 | 中低明度、沉稳 | 明度反转 |
| 渐变方向 | **对角**（↘） | **竖向**（↓） | 方向不同 |
| 构图 | 两个白色元素（波纹 + 飞机），偏右下 | 单一白色元素，横贯居中 | 元素数量不同 |
| 几何 | **曲线**（同心弧）+ **尖角**（飞机三角） | **纯正交折线** + 圆头端点 | 无一笔曲线、无一个尖角 |
| 动势 | 沿对角线向右上「飞出」 | 由左下向上升，阶梯式 | 动势方向不同 |

**关键**：两者宏观上都是「彩色圆角块 + 白色图形」，这是 Windows 图标的通用范式，不可能也不必避开。区分度来自上面四个可测量的维度，而不是「避免都用圆角块」。

## 5. 尺寸提示表（16px 可读性的工程保证）

`generate_icon.py` 里两张表按尺寸调整几何，这是 16px 不糊的核心：

| size | 底板内缩 | 线宽 |
|---|---|---|
| 16 | 0.010 | 0.175 |
| 24 | 0.020 | 0.160 |
| 32 | 0.026 | 0.148 |
| 48 | 0.032 | 0.134 |
| 64 | 0.036 | 0.124 |
| 128 | 0.040 | 0.112 |
| 256 | 0.040 | 0.110 |

小尺寸线条必须**加粗**（16px 线宽 0.175 vs 256px 的 0.110），否则 LANCZOS 缩小后糊成一团。小尺寸底板近乎满版（内缩 0.010），保证视觉重量。

`_ALPHA_FLOOR = 6`：LANCZOS 缩小时圆角外侧会残留极淡 alpha（实测 16px 四角 alpha=2），统一夹到 0，避免透明区带一层灰雾。

## 6. ICO 容器（手写，不用 Pillow 的 ICO saver）

实测 Pillow 12.3.0 的 `IcoImagePlugin._save` 对**所有**尺寸都写 PNG frame，且自存 DIB 不带 AND mask。为最大 Windows 兼容性，自行手写容器：

- **16 / 24 / 32 / 48 / 64 px** → 32bpp `BI_RGB` DIB，`biHeight = 2 × 边长`，含真实 1bpp AND mask（透明像素置位，行按 4 字节对齐）
- **128 / 256 px** → PNG frame

## 7. 自检结果

`python verify_icon.py` → **PASS 101 项，FAIL 0 项，ALL CHECKS PASSED**

覆盖项：
1. ICO `type == 1`，entry 数 7，`sizes` 恰为 `[16,24,32,48,64,128,256]`
2. 七档逐档 `getimage().load()` 均不抛异常，解码尺寸正确
3. 每档 alpha 含 0 与 255、颜色数 > 8（非单色）；16/32/64px 四角透明、中心不透明
4. 每个 DIB 帧 `biSize==40`、`biWidth==边长`、`biHeight==2×边长`、`biBitCount==32`、帧长 == `40 + w·h·4 + mask_stride·h`；128/256 为合法 PNG magic
5. sha256 与 `03-EMQX-Server/app.ico`、旧 `WinFormsApp1/app.ico` 均不同
6. `preview-256/48/32/16.png` 与 `preview-16-zoom.png`(128²)、`preview-32-zoom.png`(256²) 齐全且尺寸正确

**16px 肉眼自检结论**：`preview-16-zoom.png`（最近邻 8× 放大）轮廓清晰，白色正交信号沿完整保留三段结构，未糊成一团；底色与线条对比充足，在白色资源管理器里视觉重量与 EMQX 相当。

## 8. 24 轮探索中被证伪的方向（记录以免重犯）

| 方向 | 失败原因 |
|---|---|
| 竖向双箭头（v1，曾被装进 WinFormsApp1） | 通用「排序/交换」字形，不表达串口/MQTT；且「饱和块+粗白字形」容器语言与 EMQX 同类 |
| 浅底 + 绿色波形（v2/v3） | 白底资源管理器里视觉重量远低于 EMQX，16px 像空图标 |
| 深底示波器波形（v4） | 违反 `Theme.cs`「禁大深色底」；且对称双足仍被读成 Π/桌子 |
| 对称双足脉冲（多处复现） | 必被读成 `Π` / 桌子 / 订书钉 |
| 多脉冲 / 双脉冲波形 | 16px 时脉冲宽 ≈ 描边宽，凹槽宽度归零，填实成色块 |
| 青/靛双色描边编码方向 | 上升沿青、下降沿靛 → 看起来像「条纹旗杆」，不是波形 |
| 实心多边形填充 | 16px 反而更差，塌成柱状图 / 像素点 |
| 双节点 + 连接线（「设备→链路」） | 16px 含糊；「圆 + 块」堆叠会被读成人像 avatar |
| `>_` 终端提示符 | 各尺寸都清晰，但属通用开发者符号，与产品不够特异 |
| 芯片 + 引脚 | 各尺寸清晰，但只是「通用 IoT 硬件」，不够精确 |
| 淡雅底板 + 圆点端点 | 淡雅底板本身的问题（见上），与字形无关 |

## 9. 复现方式
